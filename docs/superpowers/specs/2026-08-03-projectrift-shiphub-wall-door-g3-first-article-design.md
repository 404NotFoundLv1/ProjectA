# ProjectRift 舰船大厅门墙首件纵向切片设计

**状态：** 五个设计部分已获用户口头批准，等待本文档复核  
**日期：** 2026-08-03  
**适用范围：** ProjectA / ProjectRift 舰船大厅模块化场景套件  
**阶段：** G3 首件资产  
**首件：** `SM_ShipHub_WallDoor_400_A`

## 1. 目标

把 400 cm 标准门墙做成 ProjectRift 第一件完整生产资产，并用单个纵向切片证明以下管线可靠：

```text
Task 8 舰船大厅设计语言
→ 首件外观锁定
→ Blender 5.2 LTS 正式建模
→ UV、烘焙与写实 PBR
→ 碰撞与标准 FBX
→ UE 5.8 独立验证地图
→ 三状态与重导入验证
→ 用户最终验收
```

本阶段以验证完整闭环为优先，不批量生产舰船大厅套件。首件通过后得到的模板、材质和验证方法，才有资格成为后续模块的生产基线。

## 2. 权威来源与冲突裁决

发生冲突时按以下顺序裁决：

1. 本规格中已经冻结的首件尺寸、边界和验收条件；
2. `docs/superpowers/specs/2026-07-31-projectrift-ship-hub-art-pipeline-design.md`；
3. Task 8 完整建模设计图及其统一 Blender 白模；
4. `docs/superpowers/specs/2026-08-01-projectrift-shiphub-complete-modeling-drawings-design.md`；
5. 已批准的舰船大厅 v9 写实视觉方向与多视角参考；
6. 早期探索图。

生成式图像只负责探索表面语言，不得修改门洞、模块边界、枢轴、拼接面或碰撞空间。现有 `/Game/ProjectRift/Maps/L_ShipLobby` 是玩法可视化 DEMO，不是本首件的几何或布局输入，并且本阶段保持不动。

## 3. 阶段边界与 Gate

### 3.1 G3.0 首件外观锁定

从 Task 8 设计中提取门墙结构和视觉语言，交付：

- 正面、背面、侧面正交设计；
- 结构分件与材质职责图；
- 损毁、临时修补、正式上线三种状态图；
- 标准人物、智能构造体与相邻墙体拼接示意。

用户批准后冻结主体轮廓、门洞、板块结构、材料职责和颜色职责。外观图不能替代尺寸权威。

### 3.2 G3.1 生产基线

- 固定使用 `D:\Blender5.2\blender.exe`；
- 固定 Blender 场景单位、50 cm 吸附网格和坐标方向；
- 用 1 m 基准件验证 Blender → FBX → UE 单位链；
- 冻结模块包围盒、门洞、枢轴和 FBX 导出预设；
- 正式资产不得依赖 UE Actor 缩放修正尺寸。

### 3.3 G3.2–G3.4 资产生产

完成正式网格、受控倒角、UV、烘焙、PBR、三种状态覆盖、简单 UCX 碰撞和导出校验。任一阻断条件失败都退回负责该问题的源文件修正。

### 3.4 G3.5 UE 验证

在独立 `L_ShipHub_ArtValidation` 地图中验证比例、拼接、法线、碰撞、灯光、状态切换、重导入稳定性和性能。不替换或修改 `L_ShipLobby`。

### 3.5 G3.6 最终验收

交付源文件、PBR 纹理、FBX、UE 资产、验证报告、授权记录和固定机位截图。完成并验证后停止，等待用户验收，不自动规划或开始下一版本。

## 4. 几何规范

| 项目 | 冻结值 |
|---|---:|
| 模块外框宽度 | 400 cm |
| 模块结构深度 | 30 cm |
| 模块总高 | 400 cm |
| 门洞净宽 | 240 cm |
| 门洞净高 | 280 cm |
| 生产吸附网格 | 50 cm |
| 常规旋转步长 | 90° |
| UE Actor Scale | `1,1,1` |

枢轴位于模块左后下角的拼接网格点。相邻模块必须能够直接吸附并形成连续墙面；不允许在 UE 内拉伸、手工偏移或复制修补版本来掩盖源几何问题。

本首件只包含结构门洞和门框，不包含可开合门扇。门扇、动画、开关交互和游戏逻辑属于后续显式启动的版本。

## 5. Blender 资产结构

首件采用“单个模块、分层生产、统一导出”的结构。建议主文件集合如下：

```text
00_REFERENCE
10_STRUCTURE
20_DETAIL
30_STATE_OVERLAY
40_COLLISION
90_EXPORT
```

- `00_REFERENCE`：尺寸框、1 m 基准件、人物和智能构造体比例、批准设计图、相邻模块参考；
- `10_STRUCTURE`：承重框架、门洞主体、墙板和主要轮廓；
- `20_DETAIL`：门框压条、检修盖板、连接件、灯槽等有功能依据的中等尺度细节；
- `30_STATE_OVERLAY`：损毁覆盖、临时修补板、少量外露线缆和状态标识；
- `40_COLLISION`：命名正确的简单 UCX 碰撞体；
- `90_EXPORT`：仅链接最终主体、必要状态附件和碰撞体，排除参考物、制作灯光和辅助对象。

细节采用三层职责：轮廓和近景功能结构使用几何；重复的中频边缘使用 Trim Sheet；磨损、编号和微表面交给材质、贴花和 Detail Normal。不得为填充空间堆积无功能零件。

导出前必须满足：Transform 已应用、Scale 为 1、尺寸和枢轴正确、无意外非流形或重复面、法线稳定、UV 和材质槽完整、碰撞不封堵门洞、FBX 三角形方向稳定。

## 7. 视觉与材质设计

### 7.1 视觉基线

整体延续已验收的舰船大厅方向：写实 PBR、中等细节密度、结构清晰、表面干净克制。第一眼应先读到门洞、承重框架和板块层次，不能先读到随机点状细节、遍布全表面的污渍或无功能零件。

颜色职责：

- 约 70% 深色承重结构；
- 约 20% 冷灰功能护板；
- 琥珀色仅用于警告和临时修补；
- 青色用于系统正式上线；
- 紫色只属于跃迁核心体系，本首件禁止使用。

### 7.2 免费生产主线

- Blender 5.2 LTS：建模、UV、烘焙和基础程序材质；
- Krita：遮罩、贴花和纹理修整；
- UE 5.8：最终主材质、材质实例、灯光和状态效果。

只有免费流程连续两轮无法达到质量标准，或对照验证确认付费工具能在同等质量下节省至少 30% 纹理生产时间时，才允许单独申请验证 Substance 等付费方案。

### 7.3 纹理与材质预算

- 墙体有效密度基线约 `512 px/m`；
- 首件独立纹理原则上使用 2048；
- 共用 Trim Sheet 上限为 4096；
- 标准通道为 Base Color、Normal、ORM；
- 发光、损毁和修补通过独立遮罩驱动；
- 不把灯光、高光或强阴影烘焙进 Base Color；
- 主体最多两个材质槽：共享舰船表面、发光/功能区域。

编号、警告、磨损和损毁痕迹优先由 `M_ShipHub_Decal`、遮罩或状态覆盖承担。共享表面使用 `M_ShipHub_Surface` 的材质实例，不直接为首件复制一套独立主材质。

## 8. 三种视觉状态

三种状态必须共用一个主体网格，并保持模块尺寸、门洞、枢轴和碰撞完全一致。

### 8.1 损毁

- 电力关闭；
- 焦痕、划伤、松动面板和故障标识集中在有结构因果的位置；
- 不做全表面均匀随机污损；
- 优先使用遮罩、贴花和可关闭覆盖件，不复制完整主体。

### 8.2 临时修补

- 少量外挂修补板和外露线缆；
- 琥珀色维护灯和临时状态标识；
- 修补附件作为独立覆盖组件，可被状态预览 Blueprint 开关；
- 不改变结构拼接边界和门洞通行空间。

### 8.3 正式上线

- 结构整洁完整；
- 青色功能灯上线；
- 保留适量使用痕迹和粗糙度变化；
- 避免全新塑料玩具质感。

`BP_ShipHub_WallDoor_400_A_StatePreview` 只负责三种视觉状态的材质参数、灯光和覆盖组件预览，不承担开门、角色交互、复制状态或正式游戏逻辑。

## 9. UE 导入与验证闭环

使用 UE 5.8 传统 FBX Static Mesh Pipeline，当前不启用 Experimental Interchange。导入内容包括主体静态网格、UCX 碰撞、Base Color/Normal/ORM/状态遮罩、材质实例和状态预览 Blueprint。

`L_ShipHub_ArtValidation` 至少包含：

- 1 m 基准体和标准人物比例参照；
- 智能构造体比例参照；
- 中性、冷色舰内和应急照明检查环境；
- 2×2 门墙模块拼接区；
- 门洞通行与第三人称镜头检查区；
- 三种状态切换区；
- 固定截图机位。

必须验证：

1. Actor Scale 为 `1,1,1`；
2. 400 × 30 × 400 cm 外框和 240 × 280 cm 门洞正确；
3. 枢轴、50 cm 吸附和连续拼接正确；
4. 法线、倒角、UV、纹理方向和材质槽正确；
5. ProjectRift 实际角色与智能构造体均能通过门洞；
6. 碰撞不封堵通道且不明显偏离网格；
7. 三种状态切换不改变主体尺寸和碰撞；
8. FBX 与纹理重导入后引用保持稳定；
9. Nanite 或 LOD 路线符合 `PerformanceBudget.md`；
10. `PRProductionValidation` 与 PIE 检查通过。

所有外部素材、纹理和工具结果在导入前必须满足 `docs/projectrift/production/AssetImportAndLicenseChecklist.md`，并在 `Config/ProjectRift/AssetLicenseRegistry.json` 建立精确记录。完全自制时也要记录来源和工具版本。

## 10. 错误处理

| 问题 | 处理方式 | 回退位置 |
|---|---|---|
| 外观图与冻结几何冲突 | 保留尺寸与白模，修订外观图 | G3.0 |
| 单位、尺寸或枢轴错误 | 重跑 1 m 基准件并修正 Blender 模板 | G3.1 |
| 非流形、法线、UV 或材质槽失败 | 修正权威 `.blend` 或纹理源，不复制修补版 | G3.2–G3.4 |
| 碰撞封堵门洞 | 重做 UCX 并重新导出 | G3.4 |
| UE 中比例或拼接错误 | 回源修正；禁止用 Actor Scale 和手工偏移补救 | G3.1–G3.5 |
| 状态切换破坏引用或碰撞 | 修正状态 Blueprint/覆盖组件职责 | G3.5 |
| 重导入改变结果 | 修正命名、导出预设或导入设置后重验 | G3.4–G3.5 |
| 授权不清 | 阻止导入；无法证明则永久淘汰 | G3.5 |
| 付费工具价值未证明 | 保持 Blender + Krita + UE 免费主线 | 当前 Gate |

只允许操作 ProjectA。Unreal MCP 只允许使用 `http://127.0.0.1:8001/mcp`，不得探测 8000 或其他项目。ProjectA 工具不可用时，只诊断并报告 ProjectA 本地阻断。

## 11. 用户验收点

### 11.1 外观 Gate

用户验收正面、背面、侧面、结构分件、材质职责和三种状态。通过后冻结主体轮廓、门洞、板块结构、材质和灯光职责。

### 11.2 DCC Gate

用户验收 Blender 正式模型、受控倒角、UV、PBR 材质和三种状态效果。通过后才允许输出正式 FBX。

### 11.3 UE Gate

用户验收实际比例、连续拼接、角色通行、碰撞、材质、灯光、状态切换、固定机位画面和重导入稳定性。

任一 Gate 未通过，只返工当前 Gate，不提前生产其他舰船模块。

## 14. 完成标准

本 G3 首件纵向切片只有在以下条件同时满足时才算完成：

1. 三个用户验收 Gate 均通过；
2. 权威 Blender 源文件与 UE 中的最终几何、比例和枢轴一致；
3. PBR、三种状态、碰撞、拼接、通行和第三人称镜头验证通过；
4. FBX 与纹理重导入结果稳定；
5. 自动验证、PIE、性能预算和授权记录通过；
6. 所有最终交付物齐全、可打开、非占位文件；
7. 未修改 `L_ShipLobby`，未开始其他模块；
8. 完成后停止并等待用户明确验收。
