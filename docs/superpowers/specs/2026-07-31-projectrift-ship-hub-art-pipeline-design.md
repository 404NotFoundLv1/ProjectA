# ProjectRift 舰船大厅模块化美术资产工作流设计

**状态：** 已由用户逐段批准  
**日期：** 2026-07-31  
**适用范围：** ProjectA / ProjectRift 舰船大厅模块化场景套件  
**当前阶段：** 仅完成工作流设计；未启动美术生产版本

## 1. 目标

为不会亲自绘画或建模的项目负责人建立一条可执行、可回退、可审计的美术生产管线，使 Codex 能协调图像生成、Blender、二维图像工具和 Unreal Engine 5.8，完成：

1. 原创视觉方向设计；
2. 受尺寸约束的概念图生产；
3. 模块化硬表面建模；
4. 写实化 PBR 材质制作；
5. UE 导入、装配和自动校验；
6. 使用正式资产重新设计并搭建舰船大厅；
7. 保留源文件、授权证据、生成记录和可重现的验收结果。

本设计优先保证可靠性、一致性、可返修性和独立商业项目可承受的生产成本。

## 2. 关键边界

### 2.1 资产先行

正确依赖关系是：

```text
ProjectRift 产品幻想
→ 原创视觉圣经
→ 模块资产规格
→ 度量白模
→ 受控概念回绘
→ 生产模型与材质
→ UE 入库与样板舱
→ 使用正式资产搭建生产地图
```

现有 `/Game/ProjectRift/Maps/L_ShipLobby` 是玩法可视化 DEMO，不是美术或布局输入：

- 不决定舰船造型、尺度、构图、空间关系或模块尺寸；
- 不作为 ImageGen 参考图；
- 不要求正式资产适配它的现有几何；
- 在正式生产版本启动前保持不动；
- 最终保留它的权威地图路径和运行时合同，但允许彻底替换 DEMO 几何与布局。

### 2.2 项目范围

本管线当前只针对舰船大厅模块化场景套件，不自动扩张到：

- 五章裂隙环境；
- 角色、敌人或 Boss；
- 武器和动画；
- 音频；
- 正式大厅版本的实现。

管线可以在未来复用，但必须由用户显式启动新的小版本。

### 2.3 ProjectA 工具边界

- Unreal MCP 只允许使用 `http://127.0.0.1:8001/mcp`；
- MCP 只服务编辑器开发，不是运行时依赖；
- 不探测或控制其他 UE 工程、编辑器、MCP 服务或资产；
- 用户已授权 Codex 在需要时安全打开或关闭 ProjectA 编辑器；
- 只有完整 UHT/C++ 构建确有需要时才关闭 ProjectA；
- 不执行 Git staging、commit、tag、push、stash、reset、restore、checkout 或分支操作。

## 3. 已批准的美术方向

### 3.1 结构基线：断脊远征舰

舰船是一艘异星迫降后被四人执勤小队逐段救活的远征舰。

主要造型比例：

- 约 65% 方形承力框架；
- 约 25% 削角护板；
- 约 10% 圆形接口；
- 允许不对称损伤；
- 功能模块必须保持统一拼装规范；
- 外露龙骨、维修肋架、外挂舱段和可见修复接口构成项目专属身份。

### 3.2 限定叙事层：裂隙共生

裂隙视觉语言不平均铺满全舰，只允许用于：

- 跃迁核心；
- 与跃迁核心直接连接的结构；
- 随章节修复逐步扩散的少量剧情层；
- 最终返航前的高权重状态变化。

禁止把紫色发光纹当作普通科幻装饰。

### 3.3 质量目标

采用写实化 PBR、中等细节密度：

- 真实尺度、大轮廓和材料可信度优先；
- 第三人称常用距离和交互站近看必须成立；
- 重复微细节主要由 Trim Sheet、Detail Normal、贴花和材质变化承担；
- 不按 AAA 照片级微细节透支小团队生产能力；
- 所有资产从第一天就考虑碰撞、LOD/Nanite、材质槽和数据体积。

### 3.4 成本原则

采用“免费主线，付费工具按验证价值启用”：

- Blender 与 UE5.8 是长期底座；
- Krita 作为免费二维清理、贴花和遮罩工具；
- ImageGen 是可替换的视觉探索环节；
- Substance 3D 等付费工具只在同一首件对照测试中证明价值后启用；
- 生成式 3D 不作为模块结构的权威生产源。

## 4. 推荐生产路线

主生产路线为“资产白模＋概念回绘”：

```mermaid
flowchart LR
    A["视觉圣经与资产简报"] --> B["Blender 真实尺寸白模"]
    B --> C["固定镜头与辅助通道"]
    C --> D["ImageGen 受控回绘"]
    D --> E["批准后的生产设定包"]
    E --> F["Blender 生产模型"]
    F --> G["PBR 材质与贴花"]
    G --> H["UE 入库与自动校验"]
    H --> I["独立样板舱"]
    I --> J["全新大厅布局"]
```

辅助路线：

- 纯概念图先行只用于早期气氛和大方向探索；
- 生成式 3D 只用于废料、小型杂物和远景原型；
- 任何生成网格进入生产前仍必须重拓扑、重定尺寸、重做 UV、碰撞和授权审查。

## 5. 四个权威真相源

| 权威层 | 内容 | 禁止事项 |
|---|---|---|
| 视觉真相 | 批准后的视觉圣经、概念图和标注表 | 不以未批准生成图改变结构 |
| 几何真相 | Blender 主文件、模块尺寸表和导出预设 | 不在 UE 临时缩放或修补源几何 |
| 运行时真相 | UE 导入资产、材质实例、Blueprint 装配和性能数据 | 不让 DCC 假设替代真实 PIE 结果 |
| 权利真相 | 来源、提示词、工具版本、人工修改和授权证据 | 权利不明的资产不得导入或引用 |

失败时必须回到负责该问题的权威源修复，不能在下游复制出 `_New`、`_Copy` 或一次性变体掩盖问题。

## 6. 目录和源文件策略

### 6.1 建议源文件目录

源文件必须位于 cooked content 之外：

```text
ProjectA/SourceArt/ProjectRift/ShipHub/
├─ Briefs/
├─ Concept/
├─ Blender/
├─ Textures/
├─ Exports/
└─ License/
```

职责：

- `Briefs`：资产简报、尺寸表、提示词和生成台账；
- `Concept`：白模渲染、探索图、批准图和结构标注；
- `Blender`：权威 `.blend` 主文件及依赖；
- `Textures`：可编辑源贴图、烘焙结果和贴花源文件；
- `Exports`：准备导入 UE 的 FBX 和纹理；
- `License`：授权声明、许可证、发票和审查记录。

### 6.2 UE 生产目录

```text
/Game/ProjectRift/ShipHub/
├─ Meshes/
├─ Materials/
├─ Textures/
├─ Blueprints/
├─ VFX/
└─ Maps/
```

所有 UE 资产遵守 `docs/projectrift/production/AssetNamingAndDirectories.md`：

- Static Mesh 使用 `SM_`；
- Texture 使用 `T_`；
- Material 使用 `M_`；
- Material Instance 使用 `MI_`；
- Blueprint 使用 `BP_`；
- Map 使用 `L_`；
- ASCII 命名、无空格；
- 不允许以 `_New`、`_Copy`、`_Duplicate` 结尾。

### 6.3 大文件版本策略

当前仓库没有 `SourceArt`，也没有为 `.blend` 和高分辨率源贴图配置 Git LFS。

正式生产前必须单独完成：

1. 确认哪些源文件进入版本控制；
2. 为大文件设计 Git LFS 规则；
3. 明确容量、备份和恢复策略；
4. 由用户执行 staging、commit 和远端操作。

在大文件策略未批准前，不批量生成或提交源资产。

## 7. Gate 总览

| Gate | 名称 | 放行条件 |
|---|---|---|
| G0 | 资产简报 | 用途、镜头距离、状态、预算、命名和禁用项齐全 |
| G1 | 度量白模 | 尺寸、枢轴、接缝、角色通行和镜头通过 |
| G2 | 概念锁定 | 白模约束的多视图、材质和状态标注一致 |
| G3 | 首件资产 | 一件代表资产完整走完模型、UV、材质、碰撞和导入 |
| G4 | 套件批产 | 只复制已由首件证明的模板和规则 |
| G5 | UE 入库 | 命名、目录、授权、碰撞、材质和 Nanite/LOD 校验通过 |
| G6 | 样板舱 | 独立关卡中的单人/四人、镜头、灯光和性能通过 |
| G7 | 正式大厅 | 新布局、玩法闭环、自动化、打包和授权交接通过 |

任一 Gate 未通过就返回上一个权威源；完整大厅不得先于样板舱开始。

## 8. 模块度量规范

### 8.1 角色与相机基线

项目 C++ 当前基线：

- 角色胶囊半径：42 cm；
- 角色胶囊半高：96 cm；
- 默认第三人称相机臂长：400 cm。

来源：

- `Source/ProjectA/ProjectACharacter.cpp`；
- `Source/ProjectA/Characters/PRCharacter.cpp`；
- `Source/ProjectA/Characters/PRCharacter.h`。

Blueprint 可能覆盖 C++ 默认值，因此所有尺寸仍需在 G1 中以实际 ProjectRift 角色 PIE 复核。

### 8.2 建议生产尺寸

| 项目 | 基线 |
|---|---:|
| UE 编辑器吸附步长 | 50 cm |
| 标准结构开间 | 400 cm |
| 模块宽度族 | 100 / 200 / 400 cm |
| 标准净高 | 400 cm |
| 主通道建议净宽 | 500 cm |
| 支线最低净宽 | 350 cm |
| 标准门净开口 | 240 × 280 cm |
| 常规模块旋转 | 90° |
| 特殊转角 | 独立 45° 模块 |

这些是待 G1 验证的生产基线，不是不可修改的最终数字。

### 8.3 枢轴与拼接

- 枢轴放在模块底部网格角点；
- 导入 UE 后 Actor Scale 必须为 1；
- 约定正方向在 Blender 场景模板中固定；
- 2–5 cm 暗缝、压条或结构梁用于吸收拼接误差；
- 禁止依赖完全共面的无缝贴合；
- 碎屑、线缆、维修板和损伤覆盖保持独立；
- 45°、弧形或非标准连接使用专用过渡件，不任意旋转普通墙板。

## 9. 首套资产家族

### 9.1 结构模块：约 14 件

- 400×400 cm 全尺寸地板；
- 200×400 cm 半尺寸地板；
- 全尺寸与半尺寸顶板；
- 100/200/400 cm 墙板；
- 400 cm 标准门墙；
- 门框和门扇；
- 内转角和外转角；
- 梁、柱和门槛。

### 9.2 变化模块：约 10 件

- 护板；
- 临时维修板；
- 格栅；
- 通风口；
- 线槽；
- 管线；
- 灯槽；
- 少量可交换表面细节。

### 9.3 功能站：6 类

- 任务；
- 仓库；
- 制造；
- 医疗；
- 职能；
- 修船。

六类站点优先共享一个标准交互底座和安装接口，外观模块不重复实现玩法逻辑。

### 9.4 英雄资产

跃迁核心单独生产：

- 允许使用裂隙限定层；
- 不进入普通墙体造型语法；
- 可使用更高贴图密度和 Nanite 评估；
- 必须支持章节修复的视觉演化。

### 9.5 三阶段状态

| 状态 | 视觉职责 |
|---|---|
| 损毁 | 断电、积尘、烟熏、缺板和裸露骨架 |
| 临时修补 | 外挂维修板、旁路线缆、混色涂装和琥珀状态灯 |
| 正式上线 | 结构归位、冷白工作光和青色功能反馈 |

三种状态尽量共享基础网格，通过覆盖件、材质参数、贴花和灯光表现，禁止复制三整套模型。

## 10. 概念图生产

### 10.1 角色分工

| 角色 | 职责 |
|---|---|
| 用户 | 在 Gate 选择接受、退回或修改原则；不要求操作绘图或建模软件 |
| Codex | 编写简报、生成版本、控制镜头、检查一致性、维护来源和授权台账 |
| ImageGen | 探索气氛、材质、损毁方式和表面细节；不是几何权威 |
| Blender | 输出尺寸准确的白模、线稿、深度、法线、ID 色块和多视图 |

### 10.2 概念循环

1. **C0 一页简报**：功能、观察距离、结构语法、色彩、材质、状态和禁用项；
2. **C1 白模输出**：正交六视图、三个透视视角、线稿、深度、法线和 ID 图；
3. **C2 九宫格探索**：只比较大色块、护板层级、损毁节奏和照明气质；
4. **C3 受控回绘**：禁止移动门洞、拼接边界、枢轴和交互空间；
5. **C4 生产设定包**：批准关键帧、多视图、材质标注、三状态、灯光和贴花清单；
6. **C5 叠图验收**：概念与白模半透明对齐，结构漂移直接退回。

### 10.3 首件概念交付物

- 1 张批准关键帧；
- 正、侧、背结构标注；
- 材质与粗糙度区间；
- 损毁、临时修补、正式上线三联图；
- 贴花、照明和发光区域清单。

### 10.4 三轮停损

- 单个方向最多三轮生成；
- 三轮后仍无法保持结构一致，则修改简报或白模；
- 不继续无上限随机生成；
- AI 图不能直接作为带光影的 Base Color；
- AI 生成的 Normal 或 ORM 不得未经验证直接进入 UE；
- 无法确认商业权利的生成结果永久淘汰。

当前内置 ImageGen 曾出现网络故障。图像生成不可用时，白模、标注和材质规范继续进行；CLI/API 付费备用路径必须在实际使用前取得用户明确授权。

## 11. 建模生产

### 11.1 工具前置条件

当前系统 PATH 中未找到 Blender。

正式首件开始前必须：

1. 安装或登记一个固定 Blender LTS 版本；
2. 记录准确可执行文件路径；
3. 验证命令行与 Python 脚本可调用；
4. 用 1 m 基准件验证 Blender→FBX→UE 的单位链；
5. 冻结场景模板和导出预设；
6. 生产期间不随意升级 Blender。

### 11.2 建模流程

1. **M0 场景模板**：单位、网格、集合、命名、相机、灯光和导出预设；
2. **M1 参数骨架**：脚本生成 100/200/400 cm 边界、接口和枢轴；
3. **M2 受控造型**：Mirror、Array、Boolean、Bevel、Weighted Normal 等非破坏修改器；
4. **M3 细节分层**：轮廓使用几何，近景功能使用模型，重复微细节交给材质；
5. **M4 碰撞与导出**：简单 UCX 或 UE 基础碰撞，门洞和凹形件单独实测；
6. **M5 批量校验**：尺寸、原点、比例、法线、UV、材质槽、非流形和 FBX 清单。

### 11.3 自动阻断条件

- Transform 未应用或 Scale 不为 1；
- 尺寸不符合约定网格；
- 枢轴不在约定位置；
- 存在意外非流形、重复面或翻转面；
- 硬边和法线出现明显黑斑；
- 普通结构件超过两个材质槽；
- 碰撞封死门洞或交互空间；
- UV、命名或导出清单不完整；
- 导出后三角形方向不稳定。

## 12. PBR 材质生产

### 12.1 免费主线

- Blender：UV、烘焙和程序化基材；
- Krita：贴花、遮罩、纹样和生成图清理；
- UE5.8：主材质、材质实例、状态参数、贴花和性能验证。

### 12.2 四层材质栈

1. **Shared Surface**：喷漆金属、裸金属、聚合物和橡胶；
2. **Trim Sheet**：护板边缘、凹槽、螺栓、格栅和灯槽；
3. **Detail / Vertex**：Detail Normal、宏观粗糙度、磨损、污渍和修补混合；
4. **Decal / Overlay**：编号、警示、维修痕迹、漏液和破损覆盖。

建议主材质家族：

- `M_ShipHub_Surface`；
- `M_ShipHub_Decal`；
- `M_ShipHub_Glass`；
- `M_ShipHub_RiftCore`。

运行时变化使用 `MI_` 材质实例，不直接编辑共享主材质。

### 12.3 色彩职责

- 约 70% 深色承力骨架；
- 约 20% 冷灰功能护板；
- 琥珀色用于警告和临时修补；
- 青色用于系统正常上线；
- 裂隙紫只属于跃迁核心和受控剧情扩散。

### 12.4 纹理预算

| 类型 | 基线 |
|---|---:|
| 普通环境感知密度 | 约 512 px/m |
| 近景交互站和英雄资产 | 约 1024 px/m |
| 共享 Trim Sheet | 最高 4096 px |
| 独立站点纹理 | 通常 2048 px |
| 跃迁核心 | 必要时 4096 px |
| 普通结构材质槽 | 最多 2 个 |

最终仍受 `docs/projectrift/production/PerformanceBudget.md` 的 4096 上限、材质实例和 Nanite/LOD 规则约束。

### 12.5 付费工具证明门

先用免费主线完成标准门墙首件。只有满足以下任一条件才建议启用 Substance：

- 同等质量和校验条件下减少至少 30% 纹理工时；
- 免费流程连续两轮无法达到批准材质效果。

付费工具仍必须保留可导出的标准 PBR 结果和源文件，不能成为不可替换的项目依赖。

## 13. UE5.8 入库协议

### 13.1 入库阶段

1. **U0 预检**：命名、最终目录、源文件、尺寸报告和授权记录完整；
2. **U1 FBX 导入**：每个资产独立，只带网格、UV、顶点色、法线和碰撞；
3. **U2 纹理导入**：Base Color 使用 sRGB，Normal/ORM 使用正确压缩和色彩空间；
4. **U3 材质装配**：关闭 FBX 自动材质/纹理创建，绑定 ProjectRift 主材质和 `MI_`；
5. **U4 状态装配**：状态资产进入统一 Blueprint，纯结构保持 Static Mesh；
6. **U5 自动校验**：运行 `-run=PRProductionValidation`；
7. **U6 PIE 验收**：单人/四人、镜头、碰撞、灯光状态和性能。

### 13.2 导入格式

首版采用 UE5.8 成熟 FBX 静态网格流程：

- 支持多个 UV、顶点色、自定义碰撞和 LOD；
- Blender 导出前控制三角化；
- 不使用当前仍属 Experimental 的 Interchange FBX 作为初始依赖；
- 在首件稳定后再评估是否使用 Python/Interchange 自动化批量导入。

参考：

- <https://dev.epicgames.com/documentation/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine?lang=en-US>
- <https://dev.epicgames.com/documentation/unreal-engine/importing-assets-using-interchange-in-unreal-engine?lang=en-US>

### 13.3 运行时装配

- 纯墙体、地板和顶板可直接作为 Static Mesh 放置；
- 带灯光、贴花和修复状态的资产使用统一 ShipHub Module Blueprint；
- 六类交互站共享 ProjectRift 已有交互合同；
- 外观 Blueprint 不重复实现任务、仓库、制造或修船逻辑；
- 只有数量和性能数据证明需要时才引入 ISM/HISM 或打包方案。

### 13.4 重导入

- 保留准确源文件路径和导入配置；
- 更新同名资产并保持引用稳定；
- 不创建 `_New`、`_Copy` 或一次性修补材质；
- 导入问题返回 Blender 或源纹理修复。

## 15. 正式大厅生产

### 15.1 唯一输入

正式布局只有两个输入：

1. ProjectRift 实际玩法空间清单；
2. 已通过 Gate 的正式资产套件。

现有 DEMO 地图不属于输入。

### 15.2 地图生产阶段

1. **L0 空间关系**：功能邻接、视线、步行时间和四人聚集点；
2. **L1 模块装配**：只使用批准套件，禁止拉伸网格填缝；
3. **L2 玩法接线**：现有交互类、出生、任务和旅行接口；
4. **L3 灯光状态**：损毁、修补和上线三级照明与导视；
5. **L4 场景叙事**：贴花、线缆、维修痕迹、生活道具和章节反馈；
6. **L5 性能验收**：四人 PIE、碰撞、交互、材质、灯影、加载和打包回归。

### 15.3 空间原则

- 任务/指挥节点是首次进入后的视觉锚点；
- 仓库、制造、武器和职能形成短准备闭环；
- 医疗区邻接公共集结空间；
- 跃迁核心是持续可见的叙事终点；
- 裂隙出发端有明确四人集结区和状态反馈；
- 主路径支持四人交错通行；
- 站点前保留交互和等待空间；
- 不依赖文字导航才能理解下一目的地；
- 不扩张成开放世界或无用途走廊。

### 15.4 安全迁移

布局先在以下隔离评审图中搭建：

```text
/Game/ProjectRift/Developer/Maps/L_ShipHub_LayoutReview
```

该地图是非生产评审夹具，不得被生产资产硬引用。

全部 Gate 通过后，才在用户明确启动的正式大厅版本中把批准内容迁入：

```text

```

原因：现有旅行、Smoke 和其他运行时系统以 `L_ShipLobby` 为权威路径。最终保留路径、真实类名和接口，但替换 DEMO 几何和布局。

## 17. 故障回退

| 故障 | 规定动作 | 回退点 |
|---|---|---|
| 图像生成不可用 | 继续白模、标注和材质规范；不擅自启用付费 API | C1 |
| 概念结构漂移 | 叠图拒收，收紧线稿、深度和 ID 约束；最多三轮 | C0/C1 |
| Blender 尺寸错误 | 重跑 1 m 基准件和场景模板；禁止在 UE 补 Scale | M0/M1 |
| UV、法线或碰撞失败 | 回源文件修复并重导入；不复制修补版 | M2–M5 |
| 授权不明确 | 阻止导入；不能证明则永久淘汰 | U0 |
| 性能超预算 | 定位材质、阴影、透明、贴花、实例或数据体积后针对性降级 | U3/L3–L5 |
| ProjectA UE/MCP 不可用 | 只诊断 ProjectA 和 8001；必要时安全重启本项目 | 当前 Gate |
