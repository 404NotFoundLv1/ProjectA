UE 入库：源资产可回溯，运行时资产可重导

先通过授权和源文件检查，再导入最终目录；不建立“随便导进来再整理”的 Incoming 垃圾区。

U0入库预检命名、目标路径、源文件、授权记录和尺寸报告齐全。
U1FBX 导入每个资产独立；只导网格、UV、顶点色、法线与碰撞。
U2纹理导入Base Color sRGB；Normal 与 ORM 使用正确压缩和色彩空间。
U3材质装配绑定 ProjectRift 主材质与 MI；禁止自动生成一次性材质。
U4状态装配需要修复状态或交互的资产进入 Blueprint；纯结构保持静态网格。
U5自动校验运行 PRProductionValidation，错误为零才能进入样板舱。
U6PIE 验收单人／四人动线、镜头、碰撞、灯光状态和性能实测。

导入协议

主格式成熟 FBX 静态网格流程；Interchange FBX 暂不作为首版依赖。
材质关闭 FBX 自动材质／贴图生成，使用受控主材质实例。
重导入源路径和导入设置固定；更新同名资产，不制造 _New／_Copy。
Nanite / LOD按资产类型决定：英雄和高复杂静态件优先评估 Nanite；简单重复件保留成本更低的 LOD。

地图放置协议

纯结构墙、地板、顶板可直接作为 Static Mesh 放置并复用。
状态资产灯光、贴花、修复覆盖件由统一 ShipHub Module Blueprint 装配。
交互站共享交互底座，外观模块不重复实现玩法逻辑。
批量重复确认数量与性能后再使用 ISM/HISM 或打包方案，不提前复杂化。
